# 雾系列「人类版」H5

雾系列给人玩的网页版。纯静态：HTML + CSS + JS，没有后端、没有构建工具、没有外部 CDN。双击 `index.html` 能玩，放 GitHub Pages 也能玩。

## 玩法（三个游戏共通）

- **种子**：默认随机种子，页面上方显示种子号。URL 带 `?seed=数字` 可以分享同一局。点「换一局」换新种子，「重新开始」重玩同一局。
- **进度**：自动保存在本机浏览器的 localStorage 里，刷新不丢。
- **复制求援提示词**：每个游戏都有这个按钮。它把玩家当前已经在屏幕上看到的信息（规则、已读记录、已获线索、当前回合状态）整理成一段提示词，玩家贴给自己的 AI（DeepSeek、GPT、Grok 都行）一起推理。本来就是给 AI 玩的游戏，人类拉 AI 帮忙是鼓励的，不算作弊。
  - 提示词**只**从“已见信息”里拼，绝不含隐藏答案、未读记录、真相。实现方式：各游戏维护一个 `seen[]`（玩家实际看到过的内容），提示词只读 `seen[]` + 当前状态。
  - 复制成功会有一个轻提示。
- **结局页**：可以点「揭晓本局真相」（`details` 折叠，玩家主动点开才显示）。换种子，真相全变。

## 各游戏移植了哪些规则

### 《白塔巷 17 号》（v2）
- 3 晚 × 4 行动点；走动不花点，看东西、问人、拿东西、开箱子花 1 点。
- 真相由种子定，三个变体：A 收件员 / B 藏人 / C 走私。信、笔记本、王阿姨、老李、信号灯、301 门后动静、结局 A/B/E 都跟着变。
- 六条主要线索：信、王阿姨的话、老李的话、笔记本、真相（读笔记本）、屋顶的信号。
- 结局：A 接手（需笔记本 + 屋顶的信号）、B 上交（需笔记本）、C 离开；集齐六条线索后，结局页会显示拼出来的完整真相（E）。
- 与 Python 版一致。默认种子 7 是变体 B（JS 版种子与 Python 版种子生成的变体不同，见下）。

### 《雾港电报局 · 午夜班》（v2）
- 三道题：谁（窃贼）、怎么进的（后门 / 窗户 / 正门）、为什么（赌债 / 治病 / 要挟），各有独立证据链。
- 一份伪造记录：窃贼栽赃给一个无辜者，声称他在作案时刻在仓库；该无辜者另有一份不在场证明（同一时刻在别处）。每局恰好两处“矛盾”：一真（关键记录）一伪（伪造记录）。
- 3 次指认机会；指认错了只告诉你哪几道题错了，不说答案。
- 与 Python 版一致。

### 《雾岛灯塔 · 守塔人》（v2）
- 30 夜；燃油 / 雾币 / 粮食 / 灯塔状况 / 声望。每天：事件 → 2 行动点 → 夜里点灯（全亮 3 油 / 半亮 1 油 / 熄灯 0 油）。
- 声望每天 -2；每天吃 1 粮食。守满 30 夜且声望 ≥ 50：留任，赢。声望归零、灯塔状况归零、或连续 3 夜熄灯：撤职，输。
- 偷油：4 个种子定的夜晚，每次少 3 燃油；巡视找线索（3 条）后可对质止损。
- 神秘访客的便宜油是掺水油：买了之后 3 夜烧油翻倍。
- 隐藏规则：船期跟着种子定的周期走（周期 2 / 3 / 4 夜 + 相位），周期夜有船 90%、非周期夜 10%。玩家靠 `船期记录`（●=有船，○=无船）自己发现规律，然后只在周期夜全亮、非周期夜省油。
- 与 Python 版一致，只有一处界面级差异（见下）。

## 与 Python 版的差异（有意为之）

1. **随机数发生器不同**：Python 用 `random.Random(seed)`，JS 用 mulberry32。所以**同一个种子号，在 JS 版和 Python 版里生成的是不同的局**（不同的变体、不同的窃贼、不同的船期周期）。同一局只在 JS 版内部可复现（同一种子号 → 同一局），URL 分享同一局只在 H5 内有效。这是静态网页的取舍：不值得为了跨语言同一种子去复现 Python 的 Mersenne Twister。规则、判定、概率分布完全一致。
2. **答案存在形式**：Python 版把答案存在 `SEALED.md`，程序里只存 SHA-256 校验；H5 是纯静态页，真相必须放在 JS 里才能渲染结局页。所以真相在 `game.js` 里是明文——玩家如果打开开发者工具翻代码能找到。但界面上绝不会主动显示：求援提示词不含真相，结局页的真相要玩家主动点「揭晓」才显示。这是静态网页的固有限制，已在界面上做了能做的隔离。
3. **灯塔点灯按钮**：Python 版允许选燃油不够的点灯方式，选了会提示燃油不够、当夜不计船期（一个容易误触的坑）。H5 直接禁用燃油不够的选项和故障时的「全亮」，避免误操作。规则（油耗、船期效果、声望变化）不变。
4. **电报局「读记录」**：Python 版是命令行 `read N`；H5 是点记录清单里的按钮。读过的记录会打勾。
5. **白塔巷「决定」**：Python 版在三晚打完后才做决定；H5 额外提供了一个「提前做最后的决定」按钮（随时可以提前结算，规则不变——提前决定时按当时手头的线索判定）。

### 《雾岛育种所》（fog-isle/，移植自 fog-isle 仓库的 fog_isle/ + play.py）
- 6 个位点 × 2 等位基因；每季种子重随机表达规则（显性/隐性/不完全显性/上位）；基因型隐藏，只显示表现型；图鉴满是 ???。图鉴只记见过哪些性状、出现在哪些个体上（性状名 + 有该性状的雾兽编号），不写表达规则——规则要靠繁殖实验自己摸索，季末点「揭晓本季真相」才显示。
- 传说目标：同时拥有 3 个随机稀有性状的雾兽，藏在图鉴末尾，随相关性状被发现而逐步揭示。
- 30 天；A、B 两位饲养员，每天每人 2 个行动点；A 行动完换 B，B 结束进入夜晚结算（随机事件、市场轮换、委托刷新）。
- 行动全移植：繁殖（1–3 只后代，丰收时 +1）、探索（30% 野雾兽 / 25% 神秘蛋 / 20% 捡 10 雾币）、买/卖市场雾兽、完成委托、买神秘蛋（20 雾币）、向对方借配种（对方回合接受才行）、和对方交易（可附加雾币）、命名。
- 事件 10 种全移植（权重与 Python 版一致）：雾夜、神秘商人、流浪雾兽、丰收、雾疫、神秘蛋、横财、访客、雾潮、静夜。
- 网页版一个人也能玩：一个人管 A、B 两边（A 行动完换 B，界面上就是换边）。也可以让 AI 当另一位饲养员：轮到 B 的时候点「复制求援提示词」，提示词开头写明“你是饲养员 B”，把 B 能看到的局面贴给你的 AI，让它帮 B 做决定。
- 求援提示词只含玩家已看到的：两边饲养员的雾兽（只写外显性状）、市场（外观 + 价格）、委托、图鉴进度（??? 保持 ???）、繁殖记录。绝不写入隐藏的基因型、表达规则的真相、传说目标的未揭示性状（图鉴本身就不标规则，所以提示词里也不会有）。
- 与 Python 版的差异：随机数发生器不同（JS mulberry32），同一种子号生成的局不同，规则一致；存档用 localStorage（JSON），随机数状态一起存，读档后随机序列不重头来；真相在 game.js 里是明文（静态页限制），界面上绝不主动显示，季末点「揭晓本季真相」才显示本季的传说条件与各性状的表达规则；输掉那一季的季末结算卡只写“传说达成 X/3”，不写条件名（条件名只在揭晓里）。

### 跑团本（fog-rpg/《灯塔熄灭之夜》、fog-company/《雾汀生物 · 白班与夜班》）
- 玩家页：开局手稿（开局电报/公司地图，直接显示）、四张角色卡（选一张，属性与技能直接用）、规则速查、一个 d100 骰子、一个调查笔记本（玩家自己记线索，存 localStorage）。
- d100 骰子：选技能 + 选难度（普通/困难技能减半/简单技能 +20 上限 95），掷 1d100，五档判定：极难成功（<= 技能/5，规则书的大成功）、困难成功（<= 技能/2）、成功（<= 技能）、失败、大失败（96–100）。结果公开显示。
- 核心按钮「一键复制 AI 主持人提示词」：把主持人剧本 + 真相 + 规则 + 角色卡 + 手稿整理成一段完整提示词，玩家贴给自己的 AI，让 AI 当主持人带团。按钮旁边写着提醒：“提示词里有剧本和真相，复制后直接粘贴，别细看”。剧本和真相只活在 JS 数据里，页面上不显示；提示词在内存里拼好、直接复制，不经过页面。
- 再一个「复制本回合求援提示词」：只含玩家自己的笔记和已拿到的手稿，用来问另一个 AI 帮忙推理。
- 《白班与夜班》的两种玩法：① 两个人、两台设备——白班把交班表导出成一段文字发给夜班，夜班导入；② 一个人玩其中一班，另一班交给 AI 主持人扮演（主持人提示词里写清楚）。交班表做成一张可填写的纸质表格样式（时间/地点/事件/处理/备注），保安登记做成打字机字体的表格。
- 手稿领取：开局的两份直接显示；其余的等主持人在剧本里发给你之后，再勾选“已拿到”，求援提示词里才会带上全文。
- 与 Python 版（跑团本原稿是 .md，没有程序）的关系：角色卡、规则、手稿、剧本、真相全文照搬原稿；跑团本没有“程序版”，所以不存在逻辑差异，只有“主持人从人变成 AI”这一种玩法差异。

## 试玩反馈修复（2026-11-14，第一期试玩后）

Arsland 试玩第一期后提了 13 项，第二期页面对照检查后一起修了。修法验证：新增 Node 测试 35 项 + 渲染测试 40 项，全部通过；第一期回归 29/29、第二期回归 83/83。

1. **file:// 下进不了游戏**：入口的 `baita-lane/` 这类目录链接、游戏页返回地图的 `../`，在 file:// 下会打开目录列表。全部改成显式的 `xxx/index.html` 和 `../index.html`（入口 6 处、6 个游戏页返回链接、4 个 JS 回地图按钮）。
2. **纸卡里的次要按钮几乎看不见**：`.btn.secondary` 原先是浅米色字 #e8dfc8 放在暖纸 #efe6d4 上，对比度约 1.1:1（白塔巷「换个地方」的房间按钮、电报局整份「记录清单」都看不清）。纸卡内的次要按钮改成深墨色字 + 细墨线边框（`.card .btn.secondary`）；暗底上的次要按钮（结局页「同一局重玩」）仍用浅色。
3. **背景没铺满**：手机上往下滚，雾夜蓝灰底色在半截就断了，下面变浅灰白。底色从 body 移到 html（html 的背景永远铺满整篇文档），html 和 body 都设 min-height:100%/100vh，去掉 body 的 `background-attachment: fixed`。
4. **灯塔行动失败也扣行动点**：线索不够点「对质」、钱不够买油买粮修缮，都会 2→1。`doAction` 改成返回 `{ ok, msg }`，失败（钱不够/线索不够/已揭穿过）不扣点，UI 只有在 ok 时才减 1 点。巡视没新线索仍算成功（它确实巡视了）。
5. **结局页一刷新就丢**：存档恢复条件里有 `!saved.ended`，已结束的局会被丢掉重开。去掉这个排除条件，ended/over 的局也恢复，刷新后直接停在结局页；结局页本来就有的「同一局重玩」按钮可重开同一局。四游戏（白塔巷/电报局/灯塔/育种所）都修了。
6. **入口地图海上小字太浅**：海上的「雾港」「雾岛」和小字说明叠在海面上，手机上认不出来。加纸色描边（`paint-order: stroke`，描边画在字形后面，等于给字加一层纸色光晕），小字从 #b9b3a4 提亮到 #e8e2d4、字号稍大。
7. **白塔巷「今晚看到的」跨晚**：原先是 seen 的最后 4 条，会跨晚。现在 seen 每条记下当晚是第几晚（`{e, t}`），「今晚看到的」按当晚过滤；求援提示词仍含全部已见信息。旧存档里的字符串 seen 兼容读取。
8. **白塔巷结局「拼出来的真相」常开**：集齐六条线索后，「拼出来的真相」是常开卡片，跟折叠的「揭晓本局真相」打架。现在收进同一个揭晓折叠里，点开才显示。
9. **电报局胜局答案写在折叠外面**：胜局卡片在折叠外面就把答案（人、手法、动机、伪造记录）写全了。现在折叠外面只留一句“破案了”+ 读了几份记录、用了几次指认，答案全收进揭晓里。另：错误指认的 toast 会残留到胜局页，进结局时清掉（common.js 新增 `hideToast()`）。
